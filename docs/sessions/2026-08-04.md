# Major Architectural Decisions

## ADR 0001

Resolve remains responsible for all native grading controls.

Palette will never attempt to replace Resolve's existing Tangent integration.

Instead, Palette extends Resolve by controlling DCTLs and OFX plugins.

---

## ADR 0002

Palette communicates with the Tangent Wave through the Tangent TIPC SDK.

It will not communicate directly over raw USB.

---

## ADR 0003

Plugin mappings should be data-driven.

Support for new plugins should primarily come from configuration rather than writing new Swift code.

---

## ADR 0004

Version 1 targets DaVinci Resolve Studio only.

Support for Capture One and other software is intentionally postponed until Resolve support is complete.

# Current Development Strategy

The project is divided into several stages.

Stage 1

Wave Explorer

Goal:

Learn the hardware completely before attempting Resolve integration.

Wave Explorer should:

- connect to the Wave
- enumerate controls
- log every event
- update OLED labels if supported

No Resolve integration.

No Accessibility.

No DCTL support.

Just hardware verification.

---

Stage 2

Palette Core

Responsible for:

- Device Manager
- Event Router
- Workspace Loader
- Logging
- OLED Manager

Still no Resolve integration.

---

Stage 3

Resolve Adapter

Research how Palette temporarily enters plugin mode while Resolve continues to own grading mode.

---

Stage 4

Plugin Support

Prototype:

- one DCTL
- Dehancer

Generalize once both prototypes succeed.

---

# Important Technical Direction

Palette should augment Resolve.

Not compete with it.

Native grading should always feel exactly like Resolve.

Plugin mode should feel like an extension of the Wave rather than a separate application.
